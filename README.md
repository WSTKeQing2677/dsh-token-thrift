# dsh-token-thrift

给 **DSH（DeepSeek Harness）** 用的插件：**在工具的返回内容进到对话之前**，先把长输出里用不上的部分收起来，但保证**任何被收起来的东西都能按路径原样取回**。

长任务里真正吃上下文的，常常不是你的问题，而是 `pwsh` 一次几百行的构建日志、同一份 JSON 被打印三遍、一份 7 万字符的测试报告。这个插件只做三件事，且都不付出额外模型调用。

## 三条规矩

### 1. 太长的输出，折中间

超过 `thresholdChars`（默认 **2.4 万字符**）的纯文本结果，保留：

- 开头 `headChars`（默认 1.4 万字符）
- 结尾 `tailChars`（默认 1.2 万字符）
- **中段所有像报错的行**（`error` / `failed` / `exception` / `traceback` / `exit code N` …），最多 `signalChars`（默认 8000 字符）

完整原文同时落盘，折叠处写明路径和取回方式：

```
[... 另省略 423 行未命中失败特征的日志。本次内容的原文 64137 字符：<路径> —— 用 read 的 offset/limit 或 grep 可精确取回 ...]
```

命中的失败行以 `• 原文` 列出：

```
[全部失败行（共 3 行；已扫描被省略区域，未发现其他失败行）]
```

**不标行号**。原因见下面「已知限制」第 2 条——宁可不说，也不给一个会被当成真行号的偏移量。

### 2. 完全重复的输出，只留一句指针

同一会话里，同一个工具返回**字节完全相同**的内容，第二次起折叠成一句：

```
[与第 2 次 pwsh 调用返回的内容完全相同（34895 字符），未重复展开。
原文可按需读取：<路径> —— ...]
```

判定看的是**输出指纹，不是调用参数**——同一条命令换个说法重跑、或者两次不同调用碰巧产生同一份输出，都能认出来。

### 3. 拿不准就不动（fail-open）

- 结果不是纯文本（图片、富内容）→ 原样放过
- 落盘失败 → 原样放过
- 替换后的文本**没有比原文更短**、或超出预算 → 原样放过
- 代码内部任何异常 → 记一条警告，返回原始结果

## 它不做什么

| 不做 | 为什么 |
|---|---|
| 不调用任何模型 | 用新 token 买旧 token 是负收益，还会加延迟 |
| 不回改历史中段 | 只在 `tools/post-execute` 那一刻动手；改历史会打掉缓存 |
| 不折叠 `read` 的结果 | 读文件是你自己划的范围，砍了只会让你重读一次 |
| 不碰你的文件、不改模型参数 | 它只改写"这一条工具结果进对话时的文本" |

`read` 不参与**折叠**，但仍参与**去重**（同一份文件被完整读两遍，第二遍会是指针）。

## 实测

| 指标 | 结果 |
|---|---|
| 受控 A/B 体积（n=6/臂） | 52,023 → 28,647 字符（**-44.9%**） |
| 受控 A/B prompt tokens | 23,308 → 12,115（**-48.0%**） |
| 质量 | **12/12 回合逐字正确** |
| 墙钟时间 | 20.2s → 18.2s（不变长） |
| 工具调用次数 | 7.00 → 5.67（差异不显著，**不变差**） |
| 真实会话回放 | 约 **-20%**（大头是 `pwsh`，不是 `read`） |

差距原因：A/B 是受控的长日志任务，真实会话里长输出没那么密集。

## 可调参数

改 `token-thrift/cordis.patch.yml` 的 `config`，改完重新 `remove_bundle` + `install_bundle` 生效。

| 字段 | 默认 | 含义 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `trim` | `true` | 是否折叠超长结果 |
| `dedupe` | `true` | 是否折叠重复结果 |
| `thresholdChars` | `24000` | 超过多少字符才考虑折叠（须 ≥1000 且 < `budgetChars`） |
| `budgetChars` | `36000` | 折叠后的上限 |
| `headChars` / `tailChars` | `14000` / `12000` | 头尾各保留多少 |
| `signalChars` | `8000` | 中段报错行的预算 |
| `dedupeMinChars` | `400` | 小于此长度不参与去重 |
| `maxEntries` | `500` | 每会话记多少条输出指纹 |

约束：`headChars + tailChars + signalChars` 不能超过 `budgetChars`，否则插件加载时报错。

## 安装

```bash
git clone https://github.com/WSTKeQing2677/dsh-token-thrift.git
```

然后在 DSH 会话里对 AI 说：

```
用 plugin_manager 安装 <克隆下来的绝对路径>
```

这是**宿主侧插件**，装完即生效，不需要刷新页面（另外两个 UI 插件才需要 F5）。

> 按路径安装只是在 profile 里建一个指向该目录的链接，**别删、别移动那个目录**。

## 关闭

对 AI 说「关掉 token 节流」，或在「设置 → 插件」里找到 `token-thrift` 禁用。也可以只关一半：把 `trim` 或 `dedupe` 设成 `false`。

保存 `cordis.patch.yml` 后需要重新安装才生效。

## 兼容性

- 只在 **DSH `0.2.1-rc.5` + Windows** 上验证过（宿主侧，与 Web UI 无关）。
- 依赖 `tools/post-execute` 的 `PostToolDecision`（返回 `{ kind: 'accept', content }`）。
- 运行期出错一律 fail-open，原样放过；**只有加载期抛错**（比如参数约束不满足）才会导致插件不启用。

## 已知限制

1. **`pwsh` 工具会先自己截断头部**（约 170 行）再把结果交出来。插件会识别结果里的 `[output truncated; full output: <路径>]`，把**原路径**指给你，而不是声称手里这份是完整的。
2. **不标行号**：正因为第 1 条，中段命中的行如果标上"相对行号"，会被当成真实行号用，实测会让模型答错方向、再花一轮去核对。错的信息比没有信息更贵。
3. **只在工具结果产生的那一刻动手**：会话历史里已经存在的旧结果不会被改写。
4. 折叠后想自己看一眼原文：直接说「把刚才那个结果完整给我看」。
